## ADDED Requirements

### Requirement: 统一分段下载模型

下载系统 SHALL 将一切下载表达为**分段任务序列**：每个逻辑下载按固定段大小
（默认 4MB，可配置）切分为有序段；小于一个段的文件是单段退化情形。业务层
SHALL 只提交任务并等待完成，不感知分段与线程细节。

#### Scenario: 一个逻辑下载的目标尺寸 > 段大小
  - **WHEN** 一个逻辑下载的目标尺寸 > 段大小
  - **THEN** 它被切分为多个段任务并行执行，段边界与目标尺寸精确对齐（尾段可小于段大小）
  - **WHEN** 一个逻辑下载的目标尺寸 ≤ 段大小
  - **THEN** 它退化为单段任务，行为与整文件下载一致


### Requirement: 传输原语语义

底层 HTTP 原语 SHALL 按 `DownloadRange(Url, Offset, Size)` 的三态语义构造请求：
`Offset > 0 && Size >= 0` 发送精确区间（`bytes=Offset-(Offset+Size-1)`）；
`Offset > 0 && Size < 0` 发送开放结尾（`bytes=Offset-`）；`Offset == 0` 为整文件
GET（不携带 Range 头）。`Size == 0` SHALL 被拒绝。

#### Scenario: 携带 Range 头的请求得到非 206 响应
  - **WHEN** 携带 Range 头的请求得到非 206 响应（如剥 Range 的代理回 200 全量）
  - **THEN** 该响应被拒绝，不交给调用方
  - **WHEN** 响应字节数与请求的 Size 不符（Size >= 0 时）
  - **THEN** 该响应被拒绝
  - **WHEN** Size == 0
  - **THEN** 调用立即失败，不发起网络 IO


### Requirement: 传输层内存硬上限

下载系统 SHALL 在**响应头到达时**校验 Content-Length：超过传输上限（默认 256MB，
可配置）立即取消请求——body 一个字节不落内存；并以进度看门狗兜底（已收字节超限
即取消，防 Content-Length 谎报或无长度流式响应）。

#### Scenario: 任一响应的 Content-Length 超过传输上限
  - **WHEN** 任一响应的 Content-Length 超过传输上限
  - **THEN** 请求在 body 下载开始前被取消，调用方收到明确失败，目标文件不产生任何写入
  - **WHEN** 响应无 Content-Length 且已收字节超过传输上限
  - **THEN** 请求被取消，同样不产生目标写入


### Requirement: 元数据语义上限

元数据资源（清单/版本公告等 JSON）的获取 SHALL 受独立于传输上限的语义上限约束
（默认 64MB，可配置）；本地 CDN 目录中的元数据文件 SHALL 在读入内存前按同一上限
预检。超限按清单损坏类错误拒收。

#### Scenario: HTTP 拉取的元数据超过元数据上限
  - **WHEN** HTTP 拉取的元数据超过元数据上限
  - **THEN** 拒收并报清单损坏类错误（传输上限仅保内存安全，语义上限保正确性）
  - **WHEN** 本地 CDN 目录中的元数据文件超过元数据上限
  - **THEN** 读入前拒绝


### Requirement: 回调驱动单锁状态机运行模型（零专用线程）

执行器 SHALL 与引擎 HTTP 线程模型贴合：HTTP 链路（连接复用、活动超时、回调串行化）
完全由引擎 `FHttpModule` 提供，执行器自身 SHALL NOT 创建任何专用下载线程。全部 job
状态 SHALL 收敛于单一状态对象，以一把锁串行化两个入口——调用线程（Submit/Cancel）
与引擎 IO 线程回调（settle 后内联完成写盘/journal/终验/落位，再补窗口）。传输并发
SHALL 由 **in-flight 窗口**（默认 24 段，可配置）决定。请求超时 SHALL 依赖引擎
curl 层的连接/活动超时，执行器不另建计时器。

#### Scenario: 一个段请求在 IO 线程完成
  - **WHEN** 一个段请求在 IO 线程完成
  - **THEN** 回调在锁内完成该段的写盘与 journal 记位，并按公平规则为窗口补位，
    保持 in-flight 数恒定直至任务完成
  - **WHEN** 窗口 × 段大小之和超过内存预算
  - **THEN** 该组合不可达（窗口为常量上界，内存峰值可静态计算）
  - **WHEN** 一条连接停滞超过引擎活动超时（默认 30s 无进度）
  - **THEN** 引擎侧完成该请求并回调失败，执行器按既有重试路径处理（不自建超时）


### Requirement: 三规则公平调度

窗口补位 SHALL 按三规则优先序选取下一段：① 收尾优先（最早入队且剩余段数 ≤ 2 的
下载优先补位）；② 公平轮转（其余按入队顺序轮转，每个下载的 in-flight 段数不超过
每下载上限，默认 4）；③ 尾段自然补位。

#### Scenario: 大文件先入队且小文件后入队
  - **WHEN** 大文件先入队且小文件后入队
  - **THEN** 小文件先于大文件完成（完成顺序贴近入队顺序，大文件不垄断窗口）
  - **WHEN** 任一下载剩余段数 ≤ 收尾阈值
  - **THEN** 其段优先于其他下载的普通段获得空位


### Requirement: journal 位图断点续传

大文件分段下载 SHALL 采用预分配 + journal 位图续传：下载前预分配目标文件全尺寸；
每段数据落盘后在 journal 记录该段完成；中断后重启 SHALL 读取 journal 只补缺段；
全部段完成并通过整文件校验后删除 journal 并落位。

#### Scenario: 下载中断后重启
  - **WHEN** 下载中断后重启
  - **THEN** 已完成段不重下，仅缺段重新获取（中断损失 ≤ 1 段）
  - **WHEN** journal 记录所有段完成
  - **THEN** 执行整文件校验（尺寸 + 可选 SHA1），通过后清理 journal 并将文件置于最终路径


### Requirement: 校验后落盘

任何下载 SHALL 在校验通过后才出现在最终路径：传输数据先进临时状态（部分文件/
预分配文件），校验（尺寸必查、SHA1 可选）通过后原子地置于目标路径；校验失败 SHALL
清理临时状态并按重试策略重试或报告失败，损坏数据绝不进入最终路径。

#### Scenario: 段数据校验失败
  - **WHEN** 段数据校验失败（尺寸不符/校验和不符）
  - **THEN** 该段数据被丢弃重取，不写入最终文件
  - **WHEN** 整文件校验失败
  - **THEN** 临时状态清理，按重试策略重新下载或报告失败


### Requirement: 重试与超时

单请求 SHALL 有超时（默认 60s）；传输失败 SHALL 按可配置次数重试（默认 3）。
取消 SHALL 安全：任何取消路径（超时/上限/外部取消）不得破坏事件/回调的投递一致性，
也不得使其他并发请求收到错误的完成信号。

#### Scenario: 单请求超过超时时限
  - **WHEN** 单请求超过超时时限
  - **THEN** 请求被取消并按重试策略重试或计入失败
  - **WHEN** 请求因超时/上限/外部取消而中止
  - **THEN** 其他并发请求的完成信号不受影响


### Requirement: 可插拔后端

传输原语 SHALL 通过可插拔接口暴露（默认引擎 HTTP 后端），自定义后端（文件映射、
P2P 等）SHALL 能在不改动执行器与业务壳的前提下替换传输。执行器的窗口调度/续传/
校验逻辑 SHALL 与后端实现无关。

#### Scenario: 业务层注入自定义后端
  - **WHEN** 业务层注入自定义后端
  - **THEN** 执行器全流程（分段/调度/续传/校验/落位）对该后端行为一致


### Requirement: 业务壳职责边界

业务壳 SHALL 保留业务职责（已完成下载的缓存命中检查、终验、落位策略），SHALL NOT
包含传输与线程管理细节；任务级失败 SHALL 整批失败并返回失败 id 列表。

#### Scenario: 任务目标在本地已存在且校验通过
  - **WHEN** 任务目标在本地已存在且校验通过
  - **THEN** 该目标跳过网络传输
  - **WHEN** 任一目标在重试上限后仍失败
  - **THEN** 整批下载失败，失败 id 列表返回给业务层，已成功目标的缓存不受破坏
