## 二、设计层评审

### 2.1 分层与依赖（好）
四模块职责清晰且依赖单向：`UnrealGamePatcherDownload`（纯传输原语，独立可测，127 项 downloadtest）← `Core`（格式 + 状态 + 编排）← `Build`（ingest/differ）← `Program`（CLI/GUI 入口）。格式层手写严格读取（错型即拒收，不静默默认）是与 `JsonIo.h:26-40` 实测放弃 FJsonObjectConverter 反射路线的决策一致的——该决策记录（净增 ~280 行 vs ~230 行）本身就是设计质量的证据。

### 2.2 事务与崩溃一致性（pak 侧教科书级，ucas 侧有一条真缝）
- **pak = 容器自身 WAL**：CoW v2 三段提交（payload flush → index+dirindex flush → footer 512 对齐单扇区写 = 唯一提交点，`FPakWriter.cpp:485-531`）；撕裂尾由 `FPakRecovery` 反向 footer 扫描截断（magic+version+几何+index SHA1 四重过滤，几何检查减法序防溢出 `FPakRecovery.cpp:113-120`）；**洞从已提交 index 的补集结构重算**（`FInPlacePakPatcher.cpp:98-120`），"标死"与"复用"被一次 index 提交天然隔离。pak 退出 backup/rollback，消除 1x 容器写放大。这套论证在代码注释里处处与实现一致。
- **sidecar 三段事务**（download→stage→apply）：pending 先落盘、apply 中每次 save 失败即 fatal（`FUpdateOrchestrator.cpp:1285-1293`）、commit 序 Committed→index 刷新→backup 清理（1571-1612）——WAL 纪律正确。
- **残余真缝 = 几何状态与文件字节非原子配对（ucas）**：L-M4 的窗口比上版记录更宽——`FUpdateOrchestrator.cpp:1448` 的 save 已把新几何洞表落盘后，本事务**任一后续目标失败**（不只需掉电）→ Rollback 恢复旧 ucas 字节但洞表留新 → 下轮 in-place patch 可向活字节写入，且 id-multiset diff 不可见。pak 已结构性根治（洞在 patcher 内从容器实算），**ucas 应照抄同一方案**（patcher 内从 utoc/ucas 实算洞、sidecar 洞表降级为统计）——这是本轮设计层的第一建议。

### 2.3 selfCheck 双路径（上轮事故的正确修复，需定退役条件）
canonical 重算 + raw-body 回退（`JsonIo.h:151-204`）经本轮独立推演确认无绕过（转义串内 needle 不可能匹配、重复键两条路径都拒、逗号剥离对任意键位精确还原）。raw 路径验证"文本完整性"而非"语义等价"（未知字段丢弃后仍过检）——可接受。**建议**：CDN 用当前发布器重发后给回退标注退役条件（或保留为永久宽松路径但写入 TECHNICAL 的格式契约节），否则永久双分支侵蚀"canonical 即契约"的清晰性。另注意 L6（TCHAR 宽度哈希）与回退耦合：跨平台移植时两条路径要一起换 UTF-8 字节哈希，宜与 FormatVersion 3 合并决策。

### 2.4 下载栈（纵深防御好，调度器契约漂移）
传输层防御纵深：header 期 Content-Length cap + progress watchdog + DeliverOnce 原子交付 + 206/长度/空响应校验 + chunk 装载 SHA1 兜底——坏数据理论上最多活一轮。journal 位图续传"宁可重传不可错传"（Seg/Total 指纹校验后才保留 staging）。**但调度器注释/头文档/代码三方漂移**（M23：代码 rule0=收尾+cap、rule1 无上限，注释说反；InFlight 只增不减）——文档承诺的 per-job 公平上限实际不存在，且 M23 的直接后果是新的 Cancel 挂死路径（本轮 N-C1）。

### 2.5 资源模型（产品化前必须改）
`ChunkCache` 整 run 驻留所有取过的 chunk 字节 + 整文件内存装配（`FUpdateOrchestrator.cpp:1267,300,331`）——全新安装内存峰值 ≈ 内容总量。demo（7.78GB / 96GB RAM）无碍，与"100GB 级"目标冲突。方向：按文件失效 cache 或流式分块写 staging。

### 2.6 质量文化（突出）
15 套件 + TestFail/TestCrash 故障注入钩点 + FIOStats 全 run I/O 记账（专捕"静默降级为全量拉取"）+ 五轮独立 review 每项带 file:line + MCP 断点级动态验证（review-dbg-2026-10-10）。测试即行为安全网的约定（新行为必须钉测试，如 indextest §4e）执行到位。
